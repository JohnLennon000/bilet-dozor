# Дозор билетов (версия для GitHub Actions) — памятка для Claude Code

Монитор билетов: по расписанию GitHub Actions опрашивает РЖД и Aviasales (Travelpayouts), сравнивает ответы с прошлыми, шлёт Web Push (и необязательно Telegram) и обновляет данные для PWA на GitHub Pages. Пользователь говорит по-русски: интерфейс, сообщения, журнал, документация и ответы ему — на русском.

## Задача пользователя (дословно)

> Создай pwa приложение с опоаещениями о доступности к покупке билетов на ржд со станции Туймазы в Москву прямым сообщением. Важно получить уведомление то возможности покупки билета на это число. Сейчас на эту дату есть поезд 301У, но билетов нет. Возможно позже добавят вагоны или пустят дополнительный поезд на время праздников. Дата на которую искать: 09.01.2027. Так же нужно отслеживание проявления в продаже билетов из Бугульмы в Москву. 09 или 10 января на самолёте. Рейс прямой. Багаж неважно. Если появились билеты то нужно присылать динамику изменений цен

Дополнено позже: сервисов может быть несколько (Туту, Т-Банк, Яндекс Путешествия, Купибилет, OneTwoTrip, Озон). Решение: (1) в уведомлении и карточке — ссылки «купить» на РЖД, Яндекс, Туту (`links` в `config.yaml`); (2) источники подключаются по одному модулем в `dozor/sources/` после проверки, что он реально отвечает. Пользователь отказался от идеи следить за соседними станциями посадки (Уфа, Белебей) — не предлагать.

## С чего начать

1. Actions → «Проверка билетов» → Run workflow с галочкой **probe** (или локально `python -m dozor probe`). Код выхода 0 — РЖД ответил и ответ разобран.
   - `blocked`/`network` — РЖД не пускает адреса GitHub: секрет `RZD_PROXY`, или self-hosted runner в России, или проверять поезд не на GitHub.
   - `schema` — формат другой: `python -m dozor probe --raw tests/fixtures`, поправить `parse_suggestions` / `parse_train_pricing` в `dozor/sources/rzd.py`, **положить настоящие ответы в `tests/fixtures/` и написать на них тест** (сейчас все ответы синтетические: `tests/helpers.py`).
   - Проверить, что 301У виден на 2027-01-09 и что группы вагонов называются правильно (`CAR_TYPES`).
2. Проверить ссылки «купить» в `config.yaml` на живых сайтах.
3. Подключить телефон, проверить настоящее уведомление и нажатие.

## Команды

```bash
pip install -r requirements.txt pytest
python -m pytest -q                                   # ~5 с
python -m dozor [--dry-run] [--force] [--force-digest] [--fixtures DIR] [--now ISO]
python -m dozor probe [--raw DIR] [--date ГГГГ-ММ-ДД]
```
`--fixtures DIR` читает `rzd-ДАТА.json` (сырой ответ train-pricing) и `flights-ДАТА.json` вместо интернета. PyPI в среде Claude недоступен: зависимости — только `requests`, `PyYAML`, `cryptography` (Web Push написан вручную в `dozor/webpush.py`, без pywebpush).

docs/                        PWA для GitHub Pages: index.html, app.js, style.css, sw.js, manifest, icons; data/ пишет сервис

## Правила кода

- **Не плодить коммиты.** Данные пишутся только при изменении (`write_if_changed`), JSON с `sort_keys`. Не добавляйте в `state`/`summary`/`history` поля, которые меняются при каждом запуске (метки «проверено сейчас» обновляются «подтверждением» не чаще раза в 30 минут: `SAVE_BEAT`, у сводки — 15). Тест `test_identical_rerun_changes_no_files` это стережёт.
- Время — целые секунды Unix, всегда параметром `now` (никаких `time.time()` в логике, которую тестируют). Москва — фиксированный UTC+3.
- Сравнение цен идёт с **последней сообщённой** ценой (`baselines`), а не с прошлой проверкой. Не ломайте при правках `diff.py`.
- Расхождение формата источника должно становиться видимой ошибкой (`SourceError`), а не тихим «билетов нет». Если группа вагонов есть, а число мест не распознано — считаем, что место есть (`approx`).
- При неполной выдаче РЖД (`NotAllTrainsReturned`) пропавший поезд не считается «закончились»: монитор переносит его из прошлого снимка.
- Рейсы (кэш Aviasales) «липнут» на 6 часов (`FLIGHT_GRACE`); проверяются раз в `flights.interval_min`, поезд — каждый запуск.
- **CSP жёсткая** (`<meta>` в `docs/index.html`): никаких inline-скриптов и `style=`; в `docs/app.js` нет innerHTML — текст только через `textContent` (стережёт `tests/test_pwa.py`). `docs/sw.js` — классический скрипт; список `SHELL` должен совпадать с файлами (тест проверяет).
- Ссылки из уведомления открываются только если это https (`safeUrl` в `sw.js`); endpoint подписки проверяется на SSRF (`validate_endpoint`: https, не IP, не localhost).
- Секреты никогда не пишутся в репозиторий. Ключ VAPID выводится из секрета (`derive_key`), chat_id Telegram хранится только запечатанным.
- Сообщения пользователю — по-русски, с неразрывными пробелами в числах (`rub()`); не заменяйте их обычными (`str.split()` их ломает — используйте `re.sub`).
- Проект не связан с репозиторием ski-tickets (билеты на горнолыжки, тот же автор) — не смешивать.

## Протокол РЖД (по открытому клиенту, не проверен вживую)

- Подсказки: `GET https://ticket.rzd.ru/api/v1/suggests?Query=…&TransportType=rail,suburban&GroupResults=true&…` → станции с кодами; «Москва» целиком — `2000000` (запасной вариант). Коды кэшируются на 30 суток в `state.station_cache`.
- Поезда: `GET /api/v1/railway-service/prices/train-pricing` с `service_provider=B2B_RZD`, `origin`, `destination`, `departureDate=ГГГГ-ММ-ДДT00:00:00`, `getByLocalTime`, `carGrouping=DontGroup`, `getTrainsFromSchedule=true`, `adultPassengersQuantity` (полный список — `search_trains`). В ответе поезда с `CarGroups` (`CarType`, `TotalPlaceQuantity` или сумма по полкам, `MinPrice`).
- `RZD_PROXY` (секрет) — прокси только для запросов к РЖД; `RZD_BASE_URL`/`TP_BASE_URL` — свой ретранслятор или тестовый сервер.

## Идеи

- Отдельные пороги для разных поездов; выгрузка истории в CSV; обратный рейс.
- Если РЖД недоступен: запасные источники (Туту, Яндекс Путешествия) — парсеров нет, только ссылки.
