# Дозор билетов

Приложение для телефона (PWA), которое следит за билетами и присылает уведомления:

- **поезд** РЖД Туймазы → Москва на 09.01.2027, любой прямой (сейчас там 301У без билетов; сработает и «добавили вагоны», и «пустили дополнительный поезд»);
- **самолёт** Бугульма → Москва, прямой, на 09 и 10 января (багаж не учитывается).

Когда билеты появляются, приходит срочное уведомление с кнопками «Купить на РЖД» и «Яндекс Путешествия» (на карточке в приложении есть и Туту).
Потом приходят изменения цены с динамикой: было → стало, минимум и максимум за время наблюдения. Раз в день, в 9:00 по Москве, приходит сводка.

Всё работает бесплатно на GitHub, свой сервер не нужен: GitHub Actions проверяет источники примерно раз в 10 минут (рейсы раз в 30),
история лежит в репозитории, приложение — на GitHub Pages. Устроено так же, как репозиторий ski-tickets.

> **Что не проверено.** Код писался в среде без доступа к сайту РЖД и к Aviasales. Логика, шифрование уведомлений и интерфейс проверены тестами
> и в браузере на выдуманных ответах, но настоящий ответ РЖД парсер ещё не видел. Первым делом запустите проверку источников (шаг 6 ниже).
> Подробный список — в конце.

## Установка (всё делается с телефона в браузере)

1. **Репозиторий.** Создайте на GitHub новый **публичный** репозиторий (например, `bilet-dozor`) и загрузите в него файлы из архива
   (Add file → Upload files; папки `.github`, `docs`, `dozor`, `push`, `state`, `tests` и файлы в корне; `.github` должна сохранить имя с точкой).
   Публичный нужен, потому что в приватном бесплатных минут Actions (2000 в месяц) не хватит на проверки каждые 10 минут.
   Всё, что видно в репозитории (даты, найденные билеты, история цен), будет открыто.
2. **Секреты.** Settings → Secrets and variables → Actions → New repository secret:
   - `TRAVELPAYOUTS_TOKEN` — токен Travelpayouts, **тот же, что в ski-tickets** (иначе рейсы не проверяются, поезд проверяется и без него);
   - `PUSH_SECRET` — любая длинная случайная строка. Из неё получается ключ уведомлений. Если её не задать, ключ получится из токена Travelpayouts,
     и при смене токена телефон придётся подключать заново;
   - необязательно: `RZD_PROXY` (см. «РЖД не отвечает»), `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (см. «Telegram»).
3. **Приложение.** Settings → Pages → Build and deployment → Deploy from a branch → `main` / `/docs` → Save.
   Адрес будет `https://<логин>.github.io/<репозиторий>/`.
4. **Права Actions.** Settings → Actions → General → Workflow permissions → Read and write permissions → Save
   (без этого проверка не сможет сохранять данные).
5. **Первый запуск.** Вкладка Actions → «Проверка билетов» → Run workflow. Если GitHub попросит включить Actions, включите.
6. **Проверка источников.** Ещё раз Run workflow, но отметьте галочку **probe**. Откройте запуск и посмотрите его Summary:
   там сказано, отвечает ли РЖД с серверов GitHub, нашлись ли станции «Туймазы» и «Москва», виден ли поезд 301У и как разобрались вагоны.
   Если всё с галочками — дальше ничего делать не нужно. Если нет, смотрите «РЖД не отвечает».
7. **Телефон.** Откройте адрес приложения.
   - Android (Chrome): меню → «Установить приложение», потом откройте его с экрана и нажмите «Включить уведомления».
   - iPhone (Safari, iOS 16.4 и новее): «Поделиться» → «На экран „Домой“», откройте приложение с экрана «Домой», потом «Включить уведомления».
   После «Включить уведомления» нажмите «Открыть GitHub» → «Commit changes». Через несколько минут придёт пробное уведомление со сводкой.

## РЖД не отвечает

Серверы GitHub находятся в США, и сайт РЖД может не отвечать на такие адреса или показывать им заглушку. Это нельзя узнать заранее, это показывает probe.
Если РЖД не отвечает (в probe «закрыл доступ», «нет связи» или «вернул не JSON»), есть три пути:

1. **Российский прокси.** Секрет `RZD_PROXY` вида `http://логин:пароль@адрес:порт`. Через него пойдут только запросы к РЖД. Прокси придётся где-то взять (платный сервис или свой небольшой сервер).
2. **Свой раннер в России.** Установите на домашний компьютер или мини-сервер «self-hosted runner» (Settings → Actions → Runners → New self-hosted runner)
   и в `.github/workflows/check.yml` замените `runs-on: ubuntu-latest` на `runs-on: self-hosted`. Проверки будут идти с вашего адреса.
3. **Оставить на GitHub только рейсы.** Тогда поезд придётся проверять вручную: в приложении всегда есть кнопка «Купить на РЖД».

Формат ответа РЖД (если probe пишет «формат мог измениться»): скопируйте блок «Фрагмент ответа» из Summary и покажите разработчику, парсер поправят.

## Настройки

Всё в [`config.yaml`](config.yaml): даты, номера поездов, станции, аэропорты, пороги уведомлений, ссылки «купить», тихие часы. Править можно прямо на GitHub с телефона
(открыть файл → карандаш → сохранить), после сохранения проверка запускается сама. Если в файле ошибка, придёт уведомление с объяснением.

- Хотите следить только за 301У? `trains: ["301У"]`. Пусто означает любой прямой поезд.
- Нужен другой порог цены? `price_min_rub` и `price_min_pct` (сообщение приходит, когда превышены **оба**).
- Хотите убрать ссылку или поправить её? Список `links`. Адреса Яндекс Путешествий и Туту составлены по образцу их сайтов и не проверены.

## Как это работает

- Цены сравниваются с **последней сообщённой** ценой, а не с прошлой проверкой: медленный рост по 20 ₽ рано или поздно наберёт порог, а колебания 4200 → 4300 → 4200 не засыпят телефон.
- Если выдача РЖД неполная (`NotAllTrainsReturned`), пропажа поезда за «билеты закончились» не считается.
- Aviasales отдаёт **кэш** поисков пользователей. Появление рейса — надёжный сигнал, а отсутствие — нет, поэтому найденный рейс держится в списке ещё 6 часов.
- Ночью (23:00–8:00 по Москве) необязательные уведомления приходят без звука. Появление билетов всегда со звуком.
- Если источник не отвечает дольше 90 минут, приходит уведомление об этом (и о том, что он снова заработал).
- Если данные не обновлялись больше часа, приложение показывает предупреждение. GitHub выключает расписание в публичном репозитории, где 60 дней нет активности. Считает ли он активностью коммиты самого сервиса, я не проверял. До 9 января остаётся меньше 70 дней, так что это может случиться: тогда в Actions появится кнопка «Enable workflow», а любое ваше изменение в репозитории (например, правка config.yaml) тоже оживит расписание.
- Данные в репозитории пишутся только при изменениях (и не чаще раза в полчаса «подтверждением»), поэтому история коммитов не засоряется.
- Время запуска у GitHub плавает: проверка «раз в 10 минут» на деле может идти реже, в часы нагрузки на 5–20 минут. Для билетов, которые разбирают за часы, этого достаточно, но это не секундомер.

## Telegram (необязательно)

Дополнительный канал на случай, если пуш не доходит. Создайте бота у @BotFather (`/newbot`), добавьте секрет `TELEGRAM_BOT_TOKEN`, откройте бота и нажмите «Запустить».
Чат определится сам (`TELEGRAM_CHAT_ID` можно не задавать).

## Что проверено и что нет

Проверено (`python -m pytest`, 85 тестов, плюс проверка в Chromium):
- сценарии «билетов нет → появились → цена изменилась → закончились», новый поезд, новые вагоны, мигание кэша Aviasales, сбои источников и восстановление;
- шифрование Web Push побайтно по тестовому вектору RFC 8291, подпись VAPID, расшифровка тестовой push-службой как в браузере, удаление умерших подписок;
- повторный запуск без изменений не меняет ни одного файла (значит, не создаёт коммит);
- интерфейс на телефоне, светлая и тёмная темы, график, офлайн, показ уведомления с двумя кнопками покупки, замена уведомления по тегу, обработка нажатий.

**Не проверено:**
1. **Живой ответ РЖД**: адреса и форма ответа взяты из открытого клиента github.com/drGOD/rzd-api, а не записаны с сайта. Возможна блокировка серверов GitHub.
2. **Шаблоны ссылок «купить»** (РЖД, Яндекс, Туту) — на живых сайтах не открывались.
3. **Живой Travelpayouts** (`prices_for_dates`): запрос собран по документации.
4. **Настоящие push-службы** (Google, Mozilla, Apple) и доступность их серверов с GitHub; **нажатие** на уведомление на настоящем телефоне; iOS.
5. **Реальное расписание GitHub Actions**: частота запусков и поведение после 60 дней.

## Разработка

```bash
pip install -r requirements.txt pytest
python -m pytest -q                                   # все тесты
python -m dozor probe                                 # живая проверка источников с этого компьютера
python -m dozor --fixtures DIR --dry-run --force      # прогон на сохранённых ответах, уведомления печатаются
```

Подробности устройства и правила кода — в [CLAUDE.md](CLAUDE.md).
